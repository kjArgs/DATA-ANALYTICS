# SQL EXERCISE 03 — JOIN

> **Prerequisite:** Complete [SQL-04-JOIN](../LESSONS/SQL-04-JOIN.md).
>
> **Database setup:** Run [SQL-DATABASE-COPY-PASTE](../SQL-DATABASE-COPY-PASTE.md) before starting.
>
> **Important:** Do not modify the database.
>
> **Goal:** Practice connecting related tables and analyzing the resulting rows.

---

## PART 1 — INNER JOIN

1. Display each order together with the name of the user who placed it.

2. Display each order together with the name of the product that was ordered.

3. Display:
   - user name
   - product name
   - order total

4. Display all orders placed by `Alice`.

5. Display all orders placed by `Diana`.

---

## PART 2 — MULTIPLE TABLES

6. Display the following for every order:
   - user's name
   - user's status
   - product name
   - product price
   - order total

7. Display the names of users who have placed an order.

8. Display the names of users who have placed an order, without duplicates.

9. Display the names of products that have been ordered.

10. Display each user's name and the product they ordered.

---

## PART 3 — LEFT JOIN

11. Display every user and their orders.

12. Make sure users who have no orders are still displayed.

13. Display every product and its orders.

14. Make sure products that have never been ordered are still displayed.

15. Find users who have never placed an order.

16. Find products that have never been ordered.

---

## PART 4 — ON VS WHERE

17. Display every user and only their orders where the order total is greater than `500`.

18. Keep users with no matching orders in the result.

19. Now write a query that filters the same result using `WHERE orders.total > 500`.

20. Compare the results of questions 18 and 19.

21. Explain why the results are different.

---

## PART 5 — GROUP BY AND AGGREGATION

22. Display each user's name and the number of orders they have placed.

23. Display each user's name and the total amount of their orders.

24. Display each product's name and the number of times it has been ordered.

25. Display each product's name and the total amount generated by its orders.

26. Find users who have placed at least `2` orders.

27. Find products that have been ordered more than once.

---

## PART 6 — COUNT(\*) VS COUNT(column)

28. Using a `LEFT JOIN`, count the number of rows associated with each user using `COUNT(*)`.

29. Using a `LEFT JOIN`, count the number of orders associated with each user using `COUNT(orders.id)`.

30. Compare the results.

31. Explain why `COUNT(*)` and `COUNT(orders.id)` can produce different results with a `LEFT JOIN`.

---

## PART 7 — COALESCE

32. Display every user's name and their total spending.

33. Replace `NULL` totals with `0`.

34. Make sure users who have never placed an order display a total spending of `0`.

---

## CHALLENGE

35. Find the user who has spent the most.

36. Find the product that has generated the most order revenue.

37. Find users who have placed at least `2` orders and display their total spending.

38. Display every user and their total spending, including users who have never placed an order.

39. Display every product and the number of times it has been ordered, including products with zero orders.

40. Find the users who have never placed an order.

41. Find the products that have never been ordered.

---

## FINAL CHALLENGE

Write a query that displays:

- user's name
- number of orders
- total amount spent

Include users who have never placed an order.

For users with no orders:

- order count should be `0`
- total spent should be `0`

Sort the result from the highest total spent to the lowest.

### Before writing the query, use the JOIN mental model:

```text
1. What am I trying to return?

2. Which table contains that data?

3. Which tables need to be connected?

4. How are they related?

5. Do I need every row from one side?

6. Which rows should be filtered?

7. Do I need groups?

8. Do I need to filter those groups?
```
